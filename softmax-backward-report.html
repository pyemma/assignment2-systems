Why FlashAttention computes D, and why dS has this shape

Softmax only reacts to contrasts between scores. D is the baseline of the upstream gradient, measured with the probabilities as weights. Subtracting it, then scaling by P, is the whole Jacobian.

dSij = Pij (dPij − Di)
Di = Σj Pij dPij = Σd Oid dOid
dSi = (diag(Pi) − Pi Pi⊤) dPi

Index i is the query. Index j is the key. Every picture below freezes one query, so Pi is a single vector of probabilities over keys. The big N×N attention matrix is just this row, repeated.

Softmax reads contrasts, so a baseline has to come back out

Adding the same constant to every score multiplies every exponential by the same factor. That factor cancels in the normalizer, and the probabilities do not move.

Going backward, the gradient has to respect that blindness. A piece of dP that is only a shared baseline cannot be turned into a score update, because no score update of the form “(c, c, c)” would have produced it. D is that baseline. The Jacobian subtracts it before anything is allowed to land in dS.

Where the matrix diag(P) − PP⊤ comes from

Fix the normalizer Z = Σk eSk and Pj = eSj / Z. Differentiating one probability with respect to one score gives two cases.

Same key, j = k

Raising Sj raises the numerator and the normalizer. The leftover is

∂Pj/∂Sj = Pj (1 − Pj)

For key 0 in the running example, 0.2 × 0.8 = 0.16. The factor (1 − Pj) is the mass currently held by everyone else, which is the only room this key has to grow.

Different key, j ≠ k

Raising Sk does not touch the numerator of Pj. It only inflates the shared normalizer, so Pj falls:

∂Pj/∂Sk = − Pj Pk

Raising S₀ pulls 0.10 off key 1 and 0.06 off key 2. Each loss is the product of the two probabilities: the key you pushed, times the key that has to give the mass up.

Both cases are one expression, Pj (δjk − Pk). As a matrix acting on the probability vector, with rows and columns indexed by keys, that is

∂Pi/∂Si = diag(Pi) − Pi Pi⊤

The diagonal matrix is the “this key’s own numerator” piece. The outer product Pi Pi⊤ is the “shared normalizer” piece: every score talks to every probability. Their difference is the competition inside the row.

Multiplying by dP is the scalar formula

The upstream gradient for this row is the vector dP. In the backward pass it arrives from the values, dPj = dO · (row j of V). Take dO = (0.4, −0.2):

key jrow of VdPj = dO · Vj
0(1, 0)0.4·1 + (−0.2)·0 = 0.40
1(0, 1)0.4·0 + (−0.2)·1 = −0.20
2(1, 1)0.4·1 + (−0.2)·1 = 0.20

Apply J. Each entry of dS is one row of J dotted with dP.

Matrix form

dS₀ = 0.16·(0.40) + (−0.10)·(−0.20) + (−0.06)·(0.20)
= 0.064 + 0.020 − 0.012 = 0.072
dS₁ = (−0.10)·(0.40) + 0.25·(−0.20) + (−0.15)·(0.20)
= −0.040 − 0.050 − 0.030 = −0.120
dS₂ = (−0.06)·(0.40) + (−0.15)·(−0.20) + 0.21·(0.20)
= −0.024 + 0.030 + 0.042 = 0.048

Same arithmetic, factored

Look at the first dot product and group the terms that contain P₀ = 0.2:

dS₀ = P₀·dP₀ − P₀·(P₀·dP₀ + P₁·dP₁ + P₂·dP₂)
= P₀ · dP₀ − P₀ · D

The parenthesis is the same for every key. It is the definition of D:

D = 0.2·(0.40) + 0.5·(−0.20) + 0.3·(0.20)
= 0.08 − 0.10 + 0.06 = 0.04

So the three dots collapse to one multiply per key:

dSj = Pj (dPj − 0.04)
= 0.2·0.36, 0.5·(−0.24), 0.3·0.16
= 0.072, −0.120, 0.048

The multiply by Pj is the saturation gate. A key with tiny probability has a tiny derivative Pj(1 − Pj), so the same gap (dPj − D) produces a small score gradient. The score would have to move a long way to change a probability that is pinned near 0, and the gradient with respect to the score is correspondingly small.

D is a weighted average, and the weights are P

D = Σj Pj dPj is the expected upstream gradient if you draw a key from the attention distribution. It is the baseline the outer product builds: (P P⊤ dP)j = Pj (P · dP) = Pj D. Every key is charged the same D, then rescaled by its own probability.

A uniform average of dP is a different number. Here the uniform mean is (0.40 − 0.20 + 0.20) / 3 ≈ 0.133, while D = 0.04. Key 1 holds half the probability and its upstream gradient is negative, so it pulls the weighted baseline down.

The uniform-baseline column is a different vector. The Jacobian’s baseline is the probability-weighted one, because the normalizer steals mass in proportion to the probability a key already holds, which is the −Pj Pk entry.

Sum of dS: 0.072 − 0.120 + 0.048 = 0. That identity is general, Σj Pj (dPj − D) = D − D · 1 = 0. The score gradient that comes out is a pure contrast, matching the fact that softmax ignores a constant shift of the scores.

Why FlashAttention forms D from O and dO

Building D as P · dP seems to require the full probability row and the full upstream row dP. Both are length-N objects. The output row is only as long as the head dimension, and it carries the same dot product.

Substitute dPj = Σd dOd Vjd and Od = Σj Pj Vjd:

Σj Pj dPj = Σj Pj Σd dOd Vjd = Σd dOd Σj Pj Vjd = Σd dOd Od

The two sums trade places. Weighting the per-key gradients by P, then summing, is the same operation as first mixing the values into O and then dotting with dO.

Path through P and dP

dP = (0.40, −0.20, 0.20)
P · dP = 0.2·0.40 + 0.5·(−0.20) + 0.3·0.20 = 0.04

Path through O and dO

O = (0.50, 0.80), dO = (0.40, −0.20)
O · dO = 0.50·0.40 + 0.80·(−0.20) = 0.20 − 0.16 = 0.04

On the backward pass the block of P is recomputed from Q and K. The elementwise line dSij = Pij (dPij − Di) then applies the Jacobian without ever writing down the N×N matrix diag(Pi) − Pi Pi⊤. For a single row that matrix is N×N and rank-deficient; the factored form needs one multiply and one subtract per entry, plus the one scalar Di shared by the whole row.

The two formulas, side by side

ObjectWhat it is in this row
diag(P) dPThe local piece. Entry j is Pj dPj.
P P⊤ dPThe coupling. Entry j is Pj D, with the same D = P · dP on every key.

So dSi = (diag(Pi) − Pi Pi⊤) dPi is the Jacobian-vector product, and dSij = Pij (dPij − Di) is that product after the outer-product term has been recognized as a single row-wise dot product. FlashAttention computes the dot product from O and dO so the N×N probability matrix does not have to be stored in order to know the baseline.

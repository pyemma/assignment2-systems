Lesson script · FlashAttention-2

How to teach the algorithm without handing over the kernel

Three beats: the memory problem, the forward invariant, and one backward identity. Each slide asks one question. The algebra and the code on the board should come from a length-4 toy you compute by hand, then from your own forward loop.

Beat 1
Vanilla

Two matmuls and a softmax. The S × S matrix is the problem.

Beat 2
Forward

Tile Q against K and V. Carry enough state that the full row never exists.

Beat 3
Backward

Start from ordinary softmax. Delete the S × S tensors one at a time.

Slide 1 · Vanilla attention

The three steps, as shapes

Write attention the way a straightforward PyTorch implementation does it, from your own code. One head, queries against keys, then a mix with values.

scoresQKᵀ / √d(S, d) × (d, S) → (S, S)
then
softmaxrow-wise(S, S) → (S, S)
then
outputPV(S, S) × (S, d) → (S, d)
SayThe math result is an (S, d) tensor. Everything else is an intermediate.
AskWhich of those three tensors has a size that grows with S², and which one do we actually need to keep?

Slide 2 · Kernel view

Separate kernels, and a round trip through HBM

The math is two matrix multiplies and an elementwise softmax. A normal PyTorch run launches a separate kernel for each, and the score matrix is written out and read back.

HBM

Q, K, and V live here. So does the S × S score matrix after the first matmul, and again after softmax, before the second matmul reads it.

On-chip

Each kernel loads a piece, computes, and stores. Softmax never sees the matmul’s registers. The S × S matrix is the traffic between them.

Use the comparison already in your profiling notes. Scores and the output mix are the big FLOP counts. Softmax is a few million FLOPs and still shows up as a large fraction of time, because it is moving that matrix.

Ask, before you show numbersFor S = 4096, d = 64, which step moves more bytes relative to the work it does: the matmuls, or the softmax?

Slide 3 · The issue

One sentence

The sentenceAttention is bandwidth-bound because the S × S matrix does not fit on chip and gets materialized. The rest of the talk is how to get the same output without ever storing that matrix.

Leave this slide up while you transition. The forward pass is the construction. The backward pass is the same construction run in reverse, plus one identity.

SayThe only tensors that grow with S and get written back are the output, and one scalar per query: the log-sum-exp. The full score matrix never exists.
AskWhy is the outer loop over query tiles and the inner loop over key/value tiles, rather than the other way around? What would you have to store if you swapped them?

Slide 5 · Online softmax

Do on the boardCompute the true softmax on the full row. Then the same row in two tiles. They match only after you rescale the first tile’s sum and output when the max changes. That rescaling is the algorithm. Write the relation you used, in words, next to the numbers.
After the numbers workThe epilogue is one more step: turn the running output and the running normalizer into the real output row, and turn the running max plus the log of the normalizer into the scalar you will need in backward.

Slide 6 · Where it lives

Point at your forward loop

Open your tiled forward. Do not paste a finished kernel onto the slide. Have the audience name the pieces.

Ask them to findWhat it must be
the running maxupdated once per key/value tile, for this query tile
the running normalizerrescaled by the change in max, then increased by this tile
the running outputsame rescaling, then a matmul of this tile’s probabilities with V
the epiloguethe lines that run only after the last key/value tile
what is savedoutput, and one scalar per query. Not the score matrix.
AskWhich lines exist only because the max changed between tiles? Cover them and say what would be wrong with the output.

Slide 7 · Backward, start ordinary

What vanilla backward stores

Do not start from the FlashAttention formula. Start from the chain rule on a softmax attention layer that did materialize the matrices.

SayBackward wants a gradient with respect to the scores. The usual implementation builds the attention matrix to get there. That matrix is exactly what the forward pass refused to store.
AskIf we refuse to save the S × S attention matrix, what is the smallest extra tensor the forward pass must have saved for us to rebuild a tile of it later?

Slide 8 · One row, length 2

Delete the Jacobian

Take a single query. Write softmax of a length-2 score row, then its Jacobian, then multiply by an upstream gradient of the probabilities. Keep the arithmetic on a 2 × 2 board.

Do until this is trueSimplify until the Jacobian is gone and you are left with an elementwise product of the probabilities with a correction. The correction is a single scalar for that query. Name the scalar. Then show it can be computed from the output row and the upstream gradient of the output, using O = PV and the corresponding expression for the gradient of P.

When the length-2 scalar is obvious, say the same algebra holds for length S. That sentence is the slide. The general equation goes up only after the toy agrees with autograd on vanilla attention.

AskWhy is that scalar a property of the query row, independent of which key/value tile you are visiting?

Slide 9 · Recompute

The same picture as the forward

With the identity in hand, the extra saved tensor is the per-query log-sum-exp. On the backward pass you reload a query tile and a key/value tile, recompute that tile of scores and probabilities, and apply the identity.

Brought in

Query tile, key tile, value tile, output tile, upstream output gradient, the saved log-sum-exp.

Written out

Gradients of Q, K, and V. The score tile is recomputed and dropped.

Check before the slide is finishedOn the same length-4 toy, compare this tiled backward to autograd on vanilla attention. Put the equation on the slide only after those two agree.

Slide 10 · Before you talk

What the audience should be able to say

  1. Vanilla attention writes an S × S matrix between two matmuls, and that traffic dominates softmax.
  2. The forward pass keeps one query tile on chip, streams key/value tiles, and carries three pieces of row state.
  3. Those three pieces match ordinary softmax on a toy row they computed both ways.
  4. Backward does not store the attention matrix. A per-query scalar, plus recomputed tiles, replaces it.
  5. They can point at your loop and name the running max, the running normalizer, the running output, and the epilogue.
If a section is still fuzzyStay on the length-4 toy. A formula that has not survived that toy does not belong on a slide yet.
